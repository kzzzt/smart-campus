# 智慧校园管理与安全平台 —— 作品说明书（初稿）

> 湛卢·智能体与原生IDE应用开发大赛
> 智慧校园管理与安全（体现"可落地"）
> 核心逻辑：为学校管理层减负，提高校园运营效率。

---

## 一、作品概述

### 作品是什么

本作品是一套面向智慧校园场景的**可落地的校园管理平台**，围绕"为学校管理层减负、提高校园运营效率"这一核心逻辑，由三大协同子系统构成：

1. **AI 教务智能客服（AI 辅导员）**：为师生提供 7×24 小时智能问答服务，覆盖请假、奖学金评定、学籍异动等高频教务场景；当 AI 无法处理的复杂情况出现时，自动生成工单并流转给对应的辅导员，形成"人机协同"处理闭环。
2. **校园能耗与安全智能预警系统**：结合物联网（IoT）数据与智算视觉模型，对宿舍违规电器使用、实验室安全隐患进行识别预警，并预测教学楼用电高峰，辅助削峰调度，实现节能减排。
3. **智能排课与教室调度系统**：利用 AI 算法（遗传算法 + 大模型约束条件理解），自动解决复杂排课冲突，并根据课程类型智能分配最合适的教室（如需电脑的课程自动排入机房）。

### 解决什么问题

- **管理侧减负**：高频、重复性咨询由 AI 自动应答，复杂问题自动流转，减少辅导员/教务人员的大量重复劳动。
- **提升效率**：排课、教室调度、能耗监管等复杂事务由算法自动完成，降低人力排错与沟通成本。
- **安全与节能**：通过 IoT + 视觉双重识别消除安全隐患，通过用电高峰预测实现节能降耗。

### 给谁用

- **学生**：7×24 小时咨询教务问题，快速得到解答或工单跟进。
- **辅导员/教务人员**：接收 AI 自动流转的复杂工单，专注高价值事务。
- **学校管理层/后勤**：实时掌握能耗与安全状态，辅助决策与调度。

## 二、创新性与湛卢能力运用

### 创新性（方案构思与技术路线的原创性）

1. **"人机协同"的客服工单闭环**：不满足于简单的问答机器人，而是构建"AI 自动应答 → 识别无法处理 → 自动生成工单 → 按类型流转辅导员 → 结果回写"的完整闭环，真正解决了"AI 客服答不上来就卡住"的落地痛点。
2. **IoT + 智算视觉双重判定**：违规电器识别同时采用 IoT 功率特征（规则判定）与智算视觉模型（图像识别）双通道，显著降低单一通道的误报率。
3. **电能高峰预测 + 削峰联动**：将能耗预测与排课系统联动，避免高能耗实验课在上课时段叠加，实现"系统级"节能减排，而非单点监控。
4. **遗传算法 + 大模型约束理解**：把大模型对自然语言排课需求的理解（如"这周多开两节实验课、需电脑的课排机房"）翻译为结构化约束，再交给遗传算法求解，兼顾排课的鲁棒性与灵活性，突破了传统硬编码排课的不灵活。

### 湛卢能力运用（AI Coding）

本项目在湛卢原生 IDE 中完成全部开发，深度运用了以下 AI Coding 能力：

- **代码智能生成**：三大子系统（客服 + 工单、能耗检测 + 预测、遗传算法排课）的核心逻辑由湛卢代码生成能力辅助高效产出。
- **智能调试**：在开发过程中借助 IDE 的智能调试定位意图识别阈值、遗传算法适应度函数等逻辑问题。
- **代码评审 / Bug 修复**：通过 AI 代码评审发现边界情况（如：复杂问题缺失关键信息时的兜底处理），并自动修复。
- **单元测试**：为三大子系统编写了覆盖核心逻辑的单元测试（`tests/`），验证意图识别、工单流转、违规检测、高峰预测、遗传算法求解等关键功能。
- **高阶功能（可扩展）**：本工程预留了 Skill / MCP / 自定义流程的接入位置——例如客服意图识别与能耗预测可通过 MCP 工具接入外部大模型与数据源，排课流程可封装为可复用 Skill（详见"可复用开发范式"）。

## 三、技术实现与应用价值

### 系统架构与工程完成度

```
                    ┌─────────────────────────────┐
                    │      智慧校园管理平台        │
                    └─────────────┬───────────────┘
              ┌───────────────────┼───────────────────┐
              │                   │                   │
     ┌────────▼───────┐  ┌───────▼────────┐  ┌───────▼────────┐
     │  子系统一       │  │  子系统二       │  │  子系统三       │
     │ AI 教务智能客服 │  │  能耗与安全预警 │  │  智能排课调度   │
     ├───────────────┤  ├───────────────┤  ├───────────────┤
     │ 意图/槽位识别  │  │ IoT 数据模拟器 │  │ 约束建模       │
     │ 知识库应答     │  │ 规则 + 视觉检测│  │ 遗传算法求解   │
     │ 工单生成与流转 │  │ 用电高峰预测   │  │ 教室智能分配   │
     └───────┬───────┘  └───────┬───────┘  └───────┬───────┘
             └──────────────────┼──────────────────┘
                      外部接口层（LLM / IoT / 视觉模型）
```

- **语言与依赖**：Python（Flask + openai + sqlite3），轻量、易部署、易演示。
- **工程完成度**（含 Web 可交互版）：
  - 提供命令行一键串联演示（`run_demo.py`）与 **Web 可交互应用**（`run_web.py`，Flask + SQLite）；
  - **Web 版**把三大子系统整合为可操作界面：AI 客服在线问答与工单流转、能耗告警与用电高峰预测、遗传算法排课求解，均在页面实时操作，**数据持久化到 SQLite**（对话记录/工单/告警/排课方案，含每次运行隔离的 `run_id`）；
  - **大模型分层接入**（`src/ai_service/llm.py`）：真实调用 OpenAI 兼容 API 做"理解"（意图识别/槽位抽取），知识库做"事实"；未配置 key / 断网 / 超时自动降级回本地规则，保证 7×24 演示永不崩、离线可跑；
  - **数据驱动的用电高峰预测**：基于历史逐小时功率的"同期均值 + 周几 + 波动"预测未来负荷，并自适应识别高峰时段，避免"预测永远为 0"的观感问题；
  - **IoT 功率 + 智算视觉双通道检测**：`src/energy/detector.py` 用 IoT 功率序列规则判定 + 视觉模型复核形成证据链，命中告警升级为高置信；视觉接口为可插拔设计（演示用模拟智算视觉，真实部署替换为 YOLO 等目标检测模型即可）；
  - **轻量登录鉴权与 CSRF 防护**：Web 版含管理员登录（session）、受保护页面/API 拦截、写操作 CSRF token 校验，提升工程安全度（演示账号 admin/SmartCampus@2026，密码来自预置账号，如需修改请更新 docs、webapp/seed_users.py 后重建数据库）；
  - 单元测试覆盖核心功能（`tests/`），共 25 项全部通过（含双通道视觉复核、登录鉴权、CSRF、Web API 集成、工单流转、高峰预测等）。

### 应用价值与落地可行性

- **智算方向**：能耗与安全识别模块天然对接智算节点上的视觉模型与大数据分析，属于典型"AI + 物联网 + 智算"落地场景。
- **校园场景**：三大子系统直接对应高校真实高频需求（咨询、排课、能耗安全），痛点明确、可量化收益。
- **落地可行性**：采用模块化、可插拔架构，数据源可替换为真实系统；遗传算法排课、规则+视觉检测均已有成熟工程可实现路径；客服模块可平滑对接现有大模型平台。
- **市场前景**：可复制推广到各类高校，具备标准化 SaaS 化能力。

## 四、展示与文档

### 演示效果

- **Web 可交互版**（`python run_web.py` → 浏览器打开 http://127.0.0.1:5000）：
  - 管理登录（演示账号 admin/SmartCampus@2026）保护三大功能页与写操作 API，未登录无法访问；
  - AI 客服在线问答：输入问题即返回自动应答或自动转工单，历史记录与工单列表实时展示；

  - 客服自动应答与工单流转过程；
  - 违规电器检测结果（含视觉复核证据）、用电高峰预测建议；
  - 遗传算法排课结果与教室智能分配方案。
