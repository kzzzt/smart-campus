## 1. 摄像头 / 图像素材（视觉识别"违规电器"）

**先说结论**：电热毯、电煮锅这类"违规电器"在桌面上往往被遮挡、观感差，**视觉可靠性不如功率特征**。建议坚持现架构的"**功率为主、视觉复核**"，视觉仅作加分项。

- **通用目标检测数据集（拿它训练/微调"电器识别"）**
  - **COCO**：Ultralytics 预训练权重（`yolo11n.pt` 等）自带该基座，含 `hair drier`、`microwave` 等家电类目。
  - **Open Images V7**（Google）：类别更广，含大量电器/居家用品图片，可离线下载。
- **自建标注（最贴合"违规电器"需求）**
  - 用手机/摄像头贴几张宿舍桌面/插座/墙角照片，用 **Ultralytics** 或开源标注工具 **Label Studio** / **Roboflow** 标注"电热毯 / 电煮锅 / 暖风机 / 小太阳"框，几十张即可做一个演示级模型。
- **视觉模型与部署（已核实规范在线上）**
  - **Ultralytics YOLO**：https://docs.ultralytics.com/ —— 一条命令 `pip install ultralytics` 即可跑 `yolo predict model=yolo11n.pt source=图片`；可导出 ONNX/TensorRT/OpenVINO 部署到边缘。**许可证 AGPL-3.0（学生/非商用可）**。
  - 示例接口（替代现在 `detector.py` 的 `vision_detect` 占位）：
    ```python
    from ultralytics import YOLO
    model = YOLO("illegal_appliance.pt")          # 你训练/微调后的权重
    def vision_detect(image_bytes):
        r = model.predict(source=image_bytes, conf=0.4)
        objs = [{"class": m.names[int(m.cls)], "conf": round(float(m.conf), 2)} for m in r[0].boxes]
        return {"detected": len(objs) > 0, "objects": [o["class"] for o in objs], "confidence": objs}
    ```

## 2. 功率 / 负荷样例数据（最贴"违规 = 高功率持续"的判定）

这几套是**非侵入式负荷识别(NILM)/家电识别的公开标准集**，可直接验证本项目 `rule_detect`（高功率持续）与 `forecast`（高峰）算法在**真实负荷**上的表现：

| 数据集 | 内容 | 说明 / 入口 |
|---|---|---|
| **UK-DALE** | 5 户整屋+逐设备功率，1s/6s，含 kettle/电暖等高功率电器 | ✅ 已核实在线，CC BY 4.0；https://jack-kelly.com/data/ 及 data.ukedc.rl.ac.uk |
| **PLAID** | 插座级高频电压电流，50+ 家电类型，专为负荷识别 | https://plaid.ucd.ie/（本次抓包 DNS 失败，请网页再确认）|
| **WHITED** | 世界家用电器数据库，稳态/瞬态负荷特征 | 官网检索 "WHITED dataset" |
| **REFIT** | 英国家庭用电，电表+设备级时序 | Strathclyde 大学 REFIT 数据集页面 |
| **AMPds** | 加拿大家庭，电/气/水多表 | AMPds 官方页 |

**接入建议**：下载其中任一（UK-DALE 最省事，有 CSV），抽一段"宿舍/家庭负荷 + 是否高功率电器"喂给现有 `rule_detect`，把 `simulator.generate_day()` 的输出替换掉即可；`forecast` 也能改成基于真实历史序列。

## 3. IoT 网关 / 硬件 / 协议 / 平台

**硬件（低成本搭真实采集，几十元级）**
- **ESP32 / ESP8266** + 电能计量模块 **PZEM-004T**（交流功率/电压/电流/电量，Modbus）或 **HLW8032**（单相计量）。做一个"宿舍/教室电表节点"。
- 电流互感器(CT)+ ADC（如 ADS1115）自搭采样。
- **Raspberry Pi** 作为**网关**：聚合多个电表节点、跑 MQTT broker 或转发到云端/上位机。

**协议**
- **MQTT**（最标准）：传感器→broker→本平台；**Modbus/RTU-TCP**（工业/智能电表，PZEM 常用）；OPC-UA（可选）。

**平台/中间件（把数据接进本项目）**
- **ThingsBoard**（✅ 已核实在线）：开源 IoT 平台，内置 MQTT 设备接入、仪表盘、报警规则——非常适合把"网关数据→可视化→报警"串起来，再回调本项目。
- **EMQX / Mosquitto**：开源 MQTT broker（轻量，本地演示够用）。
- 国内云 IoT：**阿里云 IoT 平台、华为云 IoTDA、腾讯云 IoT**（校园若用国内云对接方便）。

**最小可演示方案**：ESP32+PZEM 采集 → 本地 `mosquitto`（MQTT）→ 订阅脚本 `paho-mqtt` 收数据 → 转成 `{"room","ts","power_w"}` 交给现成的 `detector.rule_detect()` / `forecast_peak()`。**这就是 simulator 的"真实版"，改动集中在数据入口一个文件。**

## 4. 部署环境

| 方案 | 适用 | 说明 |
|---|---|---|
| **纯 CPU 本地/教室演示** | 规则判定+时序预测 | 无需 GPU，现项目即可跑；视觉可选不接 |
| **边缘视觉**：Jetson Orin/Nano 或 RK3588 | 实时图像识别 | Ultralytics 支持导出 **TensorRT**(Jetson) / **RKNN**(瑞芯微) 加速 |
| **云端训练→边缘部署** | 视觉模型 fine-tune | Colab/Kaggle/阿里云 GPU 训练，导出 ONNX 后部署 |
| **（推荐演示）功率为主、视觉为辅** | 落地与稳定性 | 现场不依赖 GPU/显卡，避免演示翻车 |
