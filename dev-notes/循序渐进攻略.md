## 阶段 1：任务一 —— 接入 API 模型

### 我的评价：**该接，但要"分层接"，不要"裸接"**

**值得接的理由**
- 现在 `src/ai_service/llm.py` 的 `chat()` 是个本地规则占位（第 10–42 行），说明书里写的"大模型语义理解"目前是空的——接上之后这条宣称才成立，这是**性价比最高的一步**。
- 改动面极小：所有调用都收敛到 `chat()` 一个入口，业务代码基本不用动。

**必须防的坑（这几点不处理，演示现场容易翻车）**
1. **断网/欠费/key 失效就整个客服崩掉** → 必须保留离线回退，`try/except` + 无 key 时走本地规则。
2. **key 泄露** → 绝不能硬编码进仓库；用环境变量 + `.env` 并确认已在 `.gitignore` 里。
3. **延迟** → 7×24 客服要"秒回"，必须设超时（建议 15~20s）并降级，否则页面转圈很尴尬。
4. **幻觉** → 教务政策（请假天数、奖学金标准）让模型自由发挥会答错。**这是最大的风险点**。
5. **测试不可复现** → 接了真实 LLM 后，单测不能依赖真模型，必须留桩/回退路径，否则 CI 会随机红。

**我的建议做法（关键）**：不要让它"裸答"。用**分层**：
- **大模型负责"理解"**：意图识别、槽位抽取、复杂问题的工单摘要 —— 让大模型真实参与决策；
- **知识库负责"事实"**：标准答案仍来自 `KNOWLEDGE_BASE`（`src/ai_service/bot.py:15-35`），或让模型只做"基于知识库的改写"（RAG 思路），不给它自由编造的空间。

这样既拿到了"真实调用大模型"的加分，又不会在评委面前说出错误的教务政策；同时无 key 时自动退回规则，演示永远不空。

### 步骤 1.3 改 `src/ai_service/llm.py`（唯一必须改的文件）
把 `chat()` 换成真实调用 + 回退：
```python
import os
from openai import OpenAI

_client = None

def _get_client():
    global _client
    if _client is None:
        _client = OpenAI(
            api_key=os.environ["LLM_API_KEY"],
            base_url=os.environ.get("LLM_BASE_URL", "https://api.openai.com/v1"),
        )
    return _client

def chat(messages: list, system: str | None = None, timeout: int = 20) -> str:
    """大模型统一入口；未配置/失败时回退本地规则，保证离线可跑。"""
    if not os.environ.get("LLM_API_KEY"):
        return _local_fallback(messages)
    try:
        conv = ([{"role": "system", "content": system}] if system else []) + list(messages)
        resp = _get_client().chat.completions.create(
            model=os.environ.get("LLM_MODEL", "gpt-4o-mini"),
            messages=conv, timeout=timeout, temperature=0.2,
        )
        return resp.choices[0].message.content or _local_fallback(messages)
    except Exception:
        return _local_fallback(messages)      # 断网/超时/欠费都不崩

def _local_fallback(messages: list) -> str:
    last = messages[-1]["content"] if messages else ""
    return f"[本地规则回复] 已收到你的问题：「{last}」。如需更精准处理，请转人工/生成工单。"
```
验证：**先不设 key** 跑 `python run_demo.py` 必须照常输出（回退生效）；**再设 key** 跑一次，看回复是否变成模型生成。

### 步骤 1.4 让意图识别真正用上大模型（可选，但推荐）
现在 `src/ai_service/intent.py:74-87` 那段"LLM 兜底"是**硬编码 if/elif**，并没有真的调用 `chat()`。想让模型参与，先把提示词改成要求 JSON（`intent.py:100-103`），再把那段换成真调用：
```python
import re   # 文件顶部补

    if score < 0.25:
        llm_used = True
        try:
            resp = chat([{"role": "user", "content": text}], system=INTENT_LLM_PROMPT)
            m = re.search(r'"intent"\s*:\s*"([^"]+)"', resp or "")
            label = m.group(1) if m else (resp or "")
            for cand in ("leave", "scholarship", "status_change", "other"):
                if cand in label:
                    intent, score = cand, 0.9
                    break
        except Exception:
            pass          # 失败就用规则结果
```
顺手可修一个真 bug：`intent.py:42-43` 的 `if hit and hit > best_score` 是**整数命中数**和**归一化分数**比大小，导致"最后一个命中的意图"总是胜出。改成先算 `score = hit/len(kws)` 再比 `score > best_score` 即可。
